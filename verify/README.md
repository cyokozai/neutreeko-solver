verify/ — 前向き探索による独立検証器
====================================

Neutreeko の強解決（後退解析）の結果を、**別の手法で書いた別の実装**で突き合わせて確かめるための道具です。

何を検証するか・なぜ独立に作るか
--------------------------------

強解決の本体は後退解析です。終局から逆向きに勝ち・負けと手数（距離）を確定させ、全局面の表を作ります。表が数百万行あると、目で見て正しさを確かめることはできません。そこで、同じ問いに**前向き探索**という別の道筋で答え、両者が一致することで正しさを担保します。

-	後退解析: 終局から逆向きに値を広げる。全局面を一度に解く。
-	前向き探索（ここ）: ある局面から深さ制限付きのミニマックス／αβ 法で読む。1 局面ずつ解く。

2 つの手法は計算の筋道がまったく違います。同じ誤りを両方が偶然同じ形で犯す可能性は低いので、突き合わせが一致すれば、どちらか一方だけを見るより強い根拠になります。この独立性を保つため、次のことを守っています。

-	`src/` 以下の後退解析のコードは読まず、読み込まず、共有もしない。標準ライブラリだけで書く。
-	書き方を意図的に変える。盤は 25 要素の配列で、ビットボードは使わない。三目の判定は、3 駒の (行, 列) 座標を整列し、隣り合う差が等しく単位方向（横・縦・両斜め）であるかで直接判定する。
-	共有するのは**規則**と**局面の文字列表記**だけ。

前向き探索そのものの正しさは `runtests.jl` で確かめています。特に、αβ 法に置換表を組み合わせると深さの扱いを誤りやすいので、枝刈りも置換表も使わない素朴なミニマックスと数千件の問い合わせで一致させています。

値の定義（後退解析の距離と同じ）
--------------------------------

`oracle(pos_str; maxdepth) -> (value, plies)`

| 返り値                 | 意味                                                                                  |
|------------------------|---------------------------------------------------------------------------------------|
| `(:loss, 0)`           | 相手が既に三目を並べている                                                            |
| `(:win, 1)`            | 手番側が 1 手で並べられる                                                             |
| `(:win, d)`            | 手番側が最短 d 手で勝てる（d ≤ maxdepth、奇数）                                       |
| `(:loss, d)`           | 手番側がどう指しても d 手で負ける。最長の抵抗で数える（d ≤ maxdepth、偶数）           |
| `(:unknown, maxdepth)` | maxdepth 手以内では決着しない                                                         |
| `(:nomove, 0)`         | 探索中に合法手 0 の局面に出会った（扱いは未確定。下記のとおり 3 対 3 では起こらない） |
| `(:invalid, 0)`        | 手番側だけが既に並んでいる到達不能な局面                                              |

-	**同一局面 3 回の引き分けは探索に入れていません。** 勝つ側が最短の手順をとると、勝ちまでの残り手数が一手ごとに厳密に減るので、同じ局面は二度と現れません。負ける側も、その手順を外れて繰り返しに持ち込むことはできません。したがって、有限手数の勝ち負けとその距離は、繰り返しの規則があってもなくても変わりません。引き分けは「どの深さでも決着しない局面」として現れます。
-	**合法手 0 の局面**は、3 対 3 の全配置 3,542,000 通り × 手番 2 通りを総当たりして 1 つも無いことを確かめました（`runtests.jl`）。`:nomove` は念のために区別して返しているだけです。

局面の文字列表記
----------------

`"<手番>:<25文字>"`。手番は `B`（黒）か `W`（白）。25 文字はマス番号 sq = 0..24 の順（a1, b1, …, e1, a2, …, e5）に `B` / `W` / `.` を並べます（sq = (行-1)×5 + (列-1)）。

初期局面（黒 b1,d1,c4 / 白 b5,d5,c2、黒番）は `B:.B.B...W.........B...W.W.` です。

使い方
------

Julia はコンテナで動かします（ローカルへのインストールは不要）。

```sh
# テスト（約 35 秒）
docker run --rm -v "$PWD":/work -w /work julia:1.11 julia verify/runtests.jl

# 後退解析の表との突き合わせ
docker run --rm -v "$PWD":/work -w /work julia:1.11 \
  julia verify/compare.jl path/to/table.tsv --maxdepth 9 [--every 100]
```

### compare.jl

入力は 1 行 `<局面文字列>\t<win|loss|draw>\t<距離>` の TSV です。空行と `#` で始まる行は読み飛ばします。

| 表の値                        | oracle に求めること                   |
|-------------------------------|---------------------------------------|
| win/loss、距離 d ≤ maxdepth   | 同じ値・同じ距離                      |
| draw、または距離 d > maxdepth | maxdepth 内で決着しない（`:unknown`） |

書式の誤り、局面文字列の誤り、`:nomove` も不一致として数えます。`:invalid` の行は検証せず、件数だけを報告します。不一致があれば列挙して終了コード 1、なければ 0 を返します。

-	`--every K` を付けると、データ行を K 行に 1 行（1, K+1, 2K+1, … 番目）だけ検証します。
-	置換表は全行で共有します。深さつきで格納し、浅い問い合わせに使うときは「残りの深さを超える勝ち負けを未決着に落とす」写像 f_r を通すので、共有しても行ごとに新しく探索した場合と結果は同じです。`runtests.jl` の「深く探索 → 浅く問い合わせ」と「1 つの置換表を異なる局面・深さで使い回す」で確かめています。

### 所要時間の目安（Docker 上の julia:1.11、1 スレッド）

| 対象                              | maxdepth         | 時間                                                 |
|-----------------------------------|------------------|------------------------------------------------------|
| 初期局面 1 つ                     | 9 / 13 / 17 / 24 | 0.04 s / 0.6 s / 5.5 s / 42 s（いずれも `:unknown`） |
| 無作為配置 2 万局面（置換表共有） | 9 / 13           | 1 行あたり 1.3 ms / 3.5 ms                           |

全局面（数百万行）を maxdepth 9 で突き合わせると数時間かかります。`--every` で間引くか、maxdepth を下げてください。

テストの内容（runtests.jl）
---------------------------

-	表記の往復、不正な表記の拒否
-	三目の判定（横・縦・両斜め、連続していない一直線、行の折り返し）
-	初期局面の合法手数 = 14（手で数えた根拠をコメントに記載）
-	滑走の規則（途中で止まれない、盤の端か駒の直前まで）
-	手組み局面: 既に負け `(:loss, 0)`、1 手勝ち `(:win, 1)`、2 手負け `(:loss, 2)`（相手の必勝手順を防げない）
-	合法手 0 の局面の総当たり（0 件）と、検出器そのものの確認
-	素朴ミニマックスと αβ の一致: 無作為局面 500 件 × 深さ 0〜5、100 件 × 深さ 6、置換表共有の 2 通りの使い方
-	置換表の深さの落とし込み f_r の単体テスト
-	盤面 8 対称で oracle の結果が変わらないこと

ファイル
--------

-	`Oracle.jl` — module `NeutreekoOracle`（規則、表記、αβ 探索、素朴ミニマックス）

-	`runtests.jl` — テスト
-	`fixtures/table_ok.tsv`, `fixtures/table_bad.tsv` — compare.jl の動作確認用の小さな表
